# ADR-001: SQLiteとSQL Serverのデータベースアダプター

## 状態

採用

## コンテキスト

開発時はローカルで完結するデータ保存が必要であり、本番ではSQL Serverを利用する。アプリケーション層を特定のDB製品に依存させず、同じ処理を両方のDBで動かす必要がある。

## 決定

- フロントエンドはVue 3、Vite、TypeScriptを使用する。
- APIはNode.js、Express、TypeScriptを使用する。
- 開発用アダプターはSQLiteのローカルファイルを使用する。
- 本番用アダプターはSQL Serverを使用する。
- アプリケーション層はDB固有のSQLやドライバーに依存せず、共通のリポジトリインターフェースを介してデータを読み書きする。
- 使用するアダプターは環境設定で選択する。接続情報やDBファイルのパスをソースコードに埋め込まない。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| 開発・本番ともSQL Server | 開発環境の準備が必要となり、ローカル単体での利用が難しい。 |
| SQLiteをアプリケーション層から直接利用 | API・ドメイン層が特定DBに依存する。 |
| SQLiteとSQL Serverを共通インターフェースのアダプターとして切替 | 開発時の簡便性と本番DBの要件を両立し、依存方向を維持できる。採用する。 |

## 影響

- DBごとに接続、スキーマ作成、パラメーター化クエリを実装する。
- SQLiteとSQL Serverで同じリポジトリ契約テストを実行する。
- トランザクションとスキーマ変更は両DBの互換性を保つ必要がある。
- 本番のSQL Serverバージョン、配置、認証、移行方法は別途決定する。
- Azure Static Web AppsからAPIへの配置構成は本ADRでは決定しない。
