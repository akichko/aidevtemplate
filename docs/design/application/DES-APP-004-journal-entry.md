# DES-APP-004: 仕訳登録・編集機能設計

## 目的

仕訳一覧から開始された新規登録または既存仕訳の編集を調整し、借方・貸方が一致する仕訳を一括して保存する。

## 関連要件・成果物

- 機能要件: REQ-F-001、REQ-F-009、REQ-F-010、REQ-F-012、REQ-F-015、REQ-F-016、REQ-F-017
- ユースケース: [UC-001](../../requirements/use-cases/UC-001-journal-entry.md)、[UC-005](../../requirements/use-cases/UC-005-journal-edit.md)
- 画面設計: [SCR-001](../ui/SCR-001-journal-entry.md)、[SCR-005](../ui/SCR-005-journal-list.md)
- ドメイン設計: [DES-DOM-001](../domain/DES-DOM-001-accounting.md)
- データ設計: [論理データ設計](../data/database-design.md)

## 処理一覧

| 処理ID | 処理 | 種別 | 説明 |
|---|---|---|---|
| APP-JRN-003 | 仕訳登録画面用データ取得 | Query | 新規時は勘定科目などの入力候補を返す。 |
| APP-JRN-004 | 仕訳登録 | Command | 入力を検証し、仕訳ヘッダーと全明細を一括保存する。 |
| APP-JRN-005 | 仕訳編集データ取得 | Query | 対象仕訳と明細を取得し、存在しない場合は対象なしを返す。 |
| APP-JRN-006 | 仕訳変更 | Command | 対象仕訳の存在、明細、貸借一致を検証し、ヘッダーと明細を一括変更する。 |
| APP-JRN-007 | 勘定科目別補助科目候補取得 | Query | 指定された勘定科目に関連付けられた補助科目候補を返す。該当する補助科目がない場合は空の候補を返す。 |
| APP-JRN-008 | 固定資産勘定用資産候補取得 | Query | 勘定科目の`systemKey`が`fixed_asset`の場合、候補照会ポートへ委譲し登録済み固定資産を返す。 |

## 入出力

| 処理 | 入力 | 成功時の出力 |
|---|---|---|
| 仕訳登録 | 取引日、摘要、各明細の`accountId`、任意の`subaccountId`、借貸区分、金額 | 登録された仕訳と仕訳ID。固定資産勘定の`subaccountId`は固定資産ID、他の勘定では通常補助科目ID。 |
| 仕訳編集データ取得 | 仕訳ID | 取引日、摘要、各明細の`accountId`、任意の`subaccountId`、借貸区分、金額、借方合計、貸方合計。 |
| 仕訳変更 | 仕訳ID、取引日、摘要、各明細の`accountId`、任意の`subaccountId`、借貸区分、金額 | 更新された仕訳。 |
| 勘定科目別補助科目候補取得 | 勘定科目識別子 | 指定された勘定科目に属する補助科目候補。 |
| 固定資産勘定用資産候補取得 | 固定資産勘定の選択状態 | 固定資産候補照会ポートが返す登録済み固定資産候補。選択した固定資産IDを仕訳明細の`subaccountId`として保持する。 |

## 処理フロー

### 新規登録

1. SCR-005から遷移情報を受け取り、新規モードでフォームを表示する。
2. 日付、摘要、明細構成を検証する。
3. 勘定科目を選択する。通常勘定科目ではAPP-JRN-007で補助科目候補を取得し、`systemKey=fixed_asset`ではAPP-JRN-008で固定資産候補を取得する。
4. 利用者は`subaccountId`を任意指定できる。通常勘定では同じ勘定科目に属する補助科目、固定資産勘定では候補として返された固定資産のIDを指定する。
5. 明細金額が正の円整数であることを検証する。
6. 借方合計と貸方合計の一致をドメイン規則で検証する。
7. 仕訳ヘッダーと明細を同一トランザクションで保存する。
8. 成功時にSCR-005へ戻り、保存した仕訳の取引年月を表示して一覧を再取得する。

### 編集

1. SCR-005から仕訳IDを受け取り、編集モードで既存の仕訳と明細を取得する。
2. 対象が存在しない場合は対象なしエラーを表示し、一覧へ戻る手段を提示する。
3. accountIdのsystem keyに応じてAPP-JRN-007またはAPP-JRN-008から候補を取得し、保存済み`subaccountId`を表示する。
4. 保存時に登録と同じ項目・金額・貸借一致検証に加え、system keyに応じて`subaccountId`の参照先が有効であることを検証する。
5. 仕訳ヘッダーと明細を同一トランザクションで更新する。旧明細と新明細の置換方法はリポジトリ実装に委譲する。
6. 成功時はSCR-005へ戻り、変更後の取引年月を表示して一覧を再取得する。
7. キャンセル時は変更を保存せず、起点の一覧へ戻る。

## 不変条件・エラー

- 登録・変更後の仕訳は借方合計と貸方合計が一致する（BR-001）。
- 明細の勘定科目が存在しない場合、ヘッダー・明細のいずれも保存しない。
- 補助科目の指定は任意とする。指定する場合、その補助科目は同じ明細の勘定科目に属していなければならない（BR-003、BR-005、REQ-F-012）。
- 固定資産勘定は`systemKey=fixed_asset`の初期勘定科目として勘定科目マスタから選択する。固定資産管理から取得した候補のIDを任意選択し、`subaccountId`に保持する（REQ-F-015、REQ-F-016）。
- 固定資産への参照は会計モジュール内で保持する。固定資産データの取得・所有は固定資産管理モジュールに委譲し、直接の永続化構造参照を行わない（ADR-004）。
- 固定資産勘定の仕訳残高は貸借対照表の資産欄で勘定科目合計として表示する（REQ-F-017）。資産ごとの個別表示切替はOPEN-DOM-015の将来構想とする。
- 編集対象が存在しない場合は404相当の対象なしを返す。
- 変更保存に失敗した場合はトランザクションをロールバックし、既存仕訳を保持する。
- 入力エラーは400相当として返し、画面に入力値を保持して表示する。
- 登録・編集成功後は保存後の仕訳取引年月を表示する仕訳一覧へ戻る。

## 依存ポート

仕訳の取得・登録・置換更新を行うリポジトリIFを使用する。DB固有の更新方法やSQLはSQLite/SQL Server各アダプターに閉じ込める。トランザクション境界は仕訳ヘッダーと全明細を含む。

固定資産候補の取得と`subaccountId`参照確認には固定資産候補照会ポートを使用する。固定資産管理への接続は連携アダプターに委譲し、会計アプリケーションから固定資産の永続化構造へ直接依存しない。固定資産勘定の合算表示を行い、個別表示切替はOPEN-DOM-015に従う。
